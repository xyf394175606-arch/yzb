# Axure 原型设计输出规范

## 使用原则

Axure 原型设计用于把需求分析结果转成可读、可评审的业务原型。原型必须同时包含线框图和需求说明。

核心原则：

- 线框图表达页面结构。
- 手机/PC 线框图内只放真实原型页面内容。
- 所有说明内容统一放右侧黄色标签区，包括字段说明、按钮说明、页面规则、状态说明、版本变化、复杂逻辑和待确认问题。
- 不在线框图内放红字说明、状态示意图、规则卡片或非真实页面内容。
- 页面跳转表达用户从哪里来、点哪里、到哪里去。
- PC 和移动端按范围分别表达，不默认一致。

## 1. 读取需求分析交接包

优先读取 `需求分析` 输出中的 `## 8. 原型设计输入`。

必须检查：

- 原型范围
- 页面层级树
- 页面清单
- 页面内容说明
- 内容展示属性
- 页面跳转
- 字段标注
- 按钮标注
- 重点说明
- 待确认但可先占位

缺少内容的处理：

- 缺页面层级树：可以根据入口关系和跳转关系保守推断，但必须在入口页或页面规则中标“页面层级关系待确认”。
- 缺页面内容说明：不要只按页面名生成空页面；在右侧黄色标签区标“页面内容待确认”。如果影响主流程，应先补充需求分析。
- 缺内容展示属性：默认不放入手机/PC线框，放入黄色页面规则并标“展示位置待确认”。
- 缺页面清单或主跳转：先补问或保守推断并标待确认。
- 缺字段来源：不要凭空加字段，标待确认。
- 缺按钮结果：可以画按钮，但不能做空点击，必须用右侧黄色标签区标“按钮结果待确认”；影响主流程时先补充需求分析。
- 缺列表行按钮的操作对象、弹窗字段或确认后状态：不能生成通用提示弹窗，必须在右侧黄色标签区标“弹窗内容待确认”；影响主流程时先补充需求分析。
- 缺 PC/移动端范围：在原型说明中写明当前假设。

## 2. 原型包结构

默认优先输出可点击的单文件 HTML 原型，便于业务、产品、设计人员直接打开评审。

单文件 HTML 原型建议包含：

```text
顶部栏：原型名称、版本、端范围、需求分析输入来源
左侧导航：按层级展示页面目录
内容区：页面线框图、右侧黄色标签区
脚本：通过 data-page 或同类方式切换页面，并支持 hash 定位
```

多文件原型在页面非常多、资源很多或用户明确要求拆分时使用，建议包含：

```text
index.html              入口页/目录页
version.html            版本说明页，可选
pages/
  pc-xxx.html           PC 页面
  mobile-xxx.html       移动端页面
assets/
  styles.css
```

如果只输出规范，不生成文件，也要按同样结构描述页面。

## 3. 目录导航层级规则

原型目录必须优先来自需求分析的 `页面层级树`，体现页面从属关系、业务入口关系和导航归属，不能把所有页面平铺成同一级，也不能只按页面名称自行分组。

推荐判断：

```text
一级：端 / 系统入口 / 大范围，例如入口、移动端、PC 后台
二级及以下：业务入口、业务模块、子页面、详情页、弹窗、抽屉、确认框、异常页
层级深度：不固定，可以是四级、五级或更多
```

示例：

```text
入口
  版本与页面目录

移动端
  个人中心
    创客中心入口
      创客中心首页
        团队成员列表
          成员详情页
        提现中心
          提现申请
          提现详情页
          驳回原因弹窗

PC 后台
  分销后台
    提现管理
      后台提现申请
      驳回弹窗
      标记打款确认弹窗
    分销配置
      分销比例配置
      新增配置弹窗
      历史版本记录
    用户管理
      用户列表-团队列表
      团队结构预览
```

错误示例：

```text
移动端
  个人中心
  创客中心
  提现
```

错误原因：如果创客中心是从个人中心进入的业务入口，它不应默认和个人中心平级。

缺少页面层级树时：

- 可以根据入口关系和页面跳转保守推断。
- 不能把推断当成确定事实。
- 必须在入口页或相关页面规则中标注“页面层级关系待确认”。

业务弹窗和状态是否进入导航，按以下规则处理：

- 有独立业务规则、字段、按钮结果、状态变化，或承担审核、驳回、通过、保存、启用、停用、关闭、打款确认、作废等业务动作的弹窗，必须进入左侧导航目录。
- 业务弹窗必须作为触发页面或所属模块的下级节点，不允许单独平铺成无来源页面。
- 点击业务弹窗目录节点时，应先进入所属页面，再打开对应弹窗，方便评审人员不点击行按钮也能看到完整页面目录层级。
- 只是纯提示、轻量确认，且没有独立字段、没有状态结果、没有复杂业务规则的弹层，可放在所属页面内，但说明必须放右侧黄色标签区。
- 等待审核、审核拒绝、空数据、无权限、提交成功、提交失败等状态，不进入左侧导航。
- 状态放在所属页面的右侧黄色标签区，用状态示意和说明表达。
- 同一页面的状态差异，不要在页面主体同时堆多个互斥状态，默认展示一个真实页面状态，其他状态放入右侧黄色标签区。
- 弹窗归属到触发它的页面或模块下，不单独放成无来源页面。
- 页面规则、字段说明、批注、黄色需求说明不进入左侧导航。

示例：

```text
PC 后台
  分销比例配置
    保存配置弹窗
    停用配置弹窗
    启用配置弹窗
```

## 4. 页面内容来源规则

页面线框必须来自需求分析中的 `页面内容说明`，不能只根据页面名称生成空页面。

生成页面前必须确认：

- 页面展示内容：页面有哪些区域、列表、卡片、表单、详情、处理记录。
- 主要字段：页面上出现哪些字段，字段来源是否清楚。
- 主要按钮/操作：页面有哪些按钮、入口、列表行点击、图标操作。
- 默认状态：页面初次打开展示什么。
- 空/异常状态：无数据、无权限、提交失败、审核失败等怎么展示。
- 说明：页面特殊规则、区域级展示口径、待确认内容。

如果页面内容缺失：

- 不生成只有标题或空壳的页面。
- 可以保留页面入口，但页面右侧黄色标签区必须标“页面内容待确认”。
- 如果该页面属于主流程，应先补充需求分析，再继续原型设计。

## 5. 真实 UI 与需求说明分离规则

生成页面前先做内容归类。只有明确属于“用户真实可见内容”且“是否进入页面线框=是”的内容，才能放进手机/PC 页面线框里。

这是底线规则：线框区域只展示真实原型页面。所有说明内容、批注内容、状态示意图、规则卡片、待确认内容，都必须放右侧黄色标签区，不允许混入手机/PC 线框。

内容放置规则：

```text
用户真实可见内容 → 放进手机/PC页面线框
页面规则说明 → 放右侧黄色标签区
内部业务规则 → 放右侧黄色标签区
后台配置/计算口径 → 默认放右侧黄色标签区，除非明确用户端展示
待接入/待确认内容 → 放右侧黄色标签区或待确认问题
原型批注 → 放右侧黄色标签区，不作为真实 UI 文案
状态示意图/状态预览 → 放右侧黄色标签区，不进入手机/PC线框
```

未明确归类的内容：

- 默认不放入真实页面线框。
- 放入右侧黄色标签区，并标“展示位置待确认”。
- 不要为了填充页面，把业务规则自动变成 UI 模块。

反例处理：

```text
提现入口点击进入提现中心；用户端不展示到账时效承诺。
```

处理：放右侧黄色标签区，不放进手机界面红字。

```text
二星团队不单独平铺，必须归属到对应一星成员下。
```

处理：放右侧黄色标签区，不放进手机界面红字。

```text
注册、买课、上课是分润来源。
```

处理：不能自动生成“分润来源摘要”模块。只有需求分析明确写“用户端首页展示分润来源摘要”时才生成；如果生成，文案必须是用户能理解的页面文案，不能使用内部命名。

## 6. 页面线框规则

页面线框优先表达业务，可以做成高保真单文件 HTML，但不能变成纯视觉稿。

页面线框只允许出现：

- 用户真实会看到的页面标题、导航、表单、列表、卡片、详情、弹窗、按钮、提示文案。
- 当前默认状态下真实会展示的页面内容。
- 真实业务弹窗的界面内容。

页面线框禁止出现：

- 红色说明文字。
- 字段解释、按钮解释、页面规则、计算口径。
- 状态示意图、状态预览块、全部状态卡片。
- “原型说明”“需求说明”“待确认”等非真实页面内容。

PC 页面要画清：

- 顶部导航或系统标题
- 左侧菜单或模块入口
- 筛选区
- 表格/列表/卡片
- 详情区域
- 表单字段
- 操作按钮
- 弹窗
- 状态、空数据、异常提示

移动端页面要画清：

- 标题栏
- 搜索/筛选入口
- 列表或卡片
- 详情字段
- 底部/顶部操作入口
- 弹窗、选择器、确认提示
- 与 PC 不同的交互方式

## 7. 页面状态展示规则

同一个页面存在多个互斥状态时，页面主体默认只展示一个状态，避免把所有状态堆在同一张线框图里。

处理规则：

- 默认状态：放在页面主体中完整展示，且必须是真实页面内容。
- 状态说明：统一放右侧黄色标签区，用状态示意块 + 文字说明描述。
- 状态示意图、状态预览块、全部状态卡片不得放进手机/PC线框。
- 黄色标签标题使用“全部状态”，不能写成“其他状态”导致漏掉当前示意状态。
- 全部状态清单必须包含默认状态、状态示意块中展示的状态、以及未画出来但需要说明的互斥状态。
- 重要状态：也不进入左侧导航，应在所属页面右侧黄色标签区单独增加更完整的状态展示。
- 状态说明要写清楚“这个状态是干嘛的”和“这个状态下页面怎么展示”。

示例：

```text
页面主体默认展示：已开通状态

状态说明 - 全部状态：
- 已开通状态：页面主体默认展示，展示“进入”按钮，点击进入创客中心首页。
- 申请开通状态：状态示意块展示，未开通用户仍展示入口，点击“申请开通”后进入等待审核状态。
- 等待审核状态：展示申请已提交提示，不允许进入创客中心。
- 已拒绝状态：展示拒绝原因和“重新申请”按钮。
```

推荐展示方式：

```text
右侧黄色标签区 - 页面规则
- 本页主体默认展示已开通状态。
- 未开通、等待审核、已拒绝为互斥状态，放在右侧黄色标签区的状态说明中展示。

跳转
进入 → 创客中心首页。

右侧黄色标签区 - 状态说明
[申请开通状态示意]

全部状态
- 已开通：页面主体默认展示，点击“进入”进入创客中心首页。
- 申请开通：右侧黄色标签区中的状态示意，点击“申请开通”后进入等待审核状态。
- 等待审核：展示申请已提交提示，不展示进入按钮。
- 已拒绝：展示拒绝原因和“重新申请”按钮。
```

不推荐：

```text
在个人中心页面主体同时展示已开通、未开通、等待审核、已拒绝四个完整卡片。
在手机/PC线框内放状态预览块或全部状态卡片。
```

## 8. 说明标注规则

说明标注是给业务、产品、设计评审看的原型批注，不是最终用户真实看到的页面文案。说明标注统一放右侧黄色标签区，不再使用线框内红字。

适合放入右侧黄色标签区的说明：

- 字段新增、隐藏、只读、必填、默认值。
- 按钮显示、隐藏、置灰、点击结果。
- 列表某列的展示规则。
- 某个状态下页面变化。
- 弹窗触发条件。
- 简短异常提示。

黄色标签可以按说明对象分组：

- 字段说明。
- 按钮说明。
- 列表说明。
- 状态说明。
- 弹窗说明。
- 页面规则。

写法示例：

```text
已报名客户手机号不可修改。
无数据时显示 --。
点击后进入客户详情页。
该按钮仅有跟进权限时显示。
```

说明不要写进手机/PC线框。长规则、跨多个元素的规则、区域展示口径、页面级规则都放右侧黄色标签区。

例如这类内容应放入右侧黄色标签区，不放在线框内部做红字：

```text
处理记录只展示状态，不展示 T+3 或到账承诺。
```

不要把用户真实可见文案写成红字批注：

- 如果用户应该看到“申请已提交，请等待后台审核”，它应作为正常页面文案展示。
- 如果只是说明这个状态下应该展示什么，就放右侧黄色标签区。
- 如果需求分析写了“红字标注”，生成原型时也必须转换为右侧黄色标签，不得在线框中渲染红字。

## 9. 右侧黄色标签区规则

右侧黄色标签区用于集中表达需求说明。它是所有非真实页面内容的唯一放置区域。

适合右侧黄色标签区：

- 字段级说明。
- 按钮级说明。
- 列表级说明。
- 页面级业务规则。
- 区域级展示口径，例如处理记录展示什么、不展示什么。
- 版本变更说明。
- 多字段联动规则。
- PC/移动端差异。
- 状态流转说明。
- 同一页面的全部状态说明。
- 状态示意图、状态预览块、全部状态卡片。
- 异常场景。
- 待确认问题。

写法示例：

```text
11月待开发
- 客户未报名时，展示客户信息，不展示学生 ITS 账号。
- 客户已报名时，展示学生信息中的联系方式、ITS 账号、家长 ITS 账号。
- 查询页面仅用于查询，不允许修改资料。
```

黄色标签区优先固定在页面右侧。复杂页面可以有多个黄色标签，但仍应在右侧标签区内分组，不放进手机/PC线框。

## 10. 页面跳转规则

页面跳转必须从需求分析的页面跳转表转化而来。

表达方式：

- 原型入口页列出所有页面。
- 按钮点击结果放右侧黄色标签区，或通过真实弹窗/页面跳转表达。
- 页面之间用箭头或链接表达跳转。
- 弹窗作为弹窗节点或页面内弹窗示意展示。

跳转说明要包含：

- 起始页面
- 触发操作
- 目标页面或弹窗
- 结果说明
- 异常时停留在哪个页面

## 11. 字段和按钮转换规则

字段转换：

- 字段表中的字段应出现在对应页面。
- 字段来源不清楚时，不直接定稿，用右侧黄色标签区写待确认。
- 展示/编辑规则如果是用户真实可见状态，体现在 UI；如果是说明，放右侧黄色标签区。

按钮转换：

- 按钮表中的操作应出现在对应页面。
- 点击结果要体现在跳转、弹窗、状态变化或右侧黄色标签区中。
- 显示/隐藏/置灰规则要用右侧黄色标签区说明。
- 每个可点击按钮必须有结果，不能做空点击。
- 如果按钮跳转到新页面，目标页面必须有页面内容说明，不能只有页面标题。
- 如果按钮打开弹窗，弹窗必须说明展示字段、按钮、确认/取消结果。
- 如果按钮改变状态，必须说明变化前状态、变化后状态、页面展示变化。
- 如果按钮结果不明，按钮旁或页面规则中标“按钮结果待确认”；影响主流程时先补充需求分析。

字段和按钮不能混在一起。

## 12. 列表行按钮与业务弹窗规则

列表或表格中的行按钮，不能用浏览器 alert 或通用说明弹窗代替真实业务弹窗。

禁止用以下内容替代业务弹窗：

```text
原型说明：审核通过 的业务结果已在本页红字或黄色说明区标注。
```

生成列表行按钮时，先确认：

- 操作对象：当前行记录，例如当前提现申请、当前客户、当前订单。
- 当前行关键字段：申请人、联系方式、金额、状态、收款信息等。
- 业务动作：审核通过、驳回、标记成功、查看、编辑、停用等。
- 弹窗或目标页面展示内容。
- 确认后结果：状态变化、页面刷新、按钮变化、是否回到列表。
- 取消后结果：关闭弹窗、停留当前页、记录不变。

业务弹窗必须包含：

- 弹窗标题。
- 字段区，展示当前行关键字段。
- 操作说明或输入项，例如驳回原因。
- 取消按钮。
- 确认按钮。
- 确认后的状态变化或页面变化说明。

后台提现申请示例：

```text
审核通过确认弹窗
- 申请人：张同学家长
- 联系方式：138****3201
- 提现金额：¥500.00
- 收款银行：招商银行
- 收款人：张三
- 银行卡号：6225 **** 1829
- 当前状态：待审核
- 按钮：取消、确认通过
- 确认后：状态变为待打款/已审核通过，列表刷新
- 取消后：关闭弹窗，状态不变
```

```text
驳回弹窗
- 展示申请人、提现金额、当前状态
- 填写驳回原因，原因必填
- 按钮：取消、确认驳回
- 确认后：状态变为已驳回
- 用户端提现详情展示驳回原因
- 取消后：关闭弹窗，状态不变
```

```text
打款确认弹窗
- 展示申请人、联系方式、提现金额、收款信息、当前状态
- 按钮：取消、确认已打款
- 确认后：状态变为已打款/已完成，列表刷新
- 取消后：关闭弹窗，状态不变
```

如果需求分析没有说明弹窗展示字段：

- 不自行编造完整字段。
- 在所属页面右侧黄色标签区标“弹窗内容待确认”。
- 可以保留按钮和弹窗占位，但弹窗内必须明确待确认项。
- 主流程依赖该弹窗时，先补充需求分析再生成最终原型。

## 13. 版本说明和入口页

当原型涉及多个页面、多个版本或多端时，应增加入口页或版本说明页。

版本说明页建议包含：

```markdown
| 版本/阶段 | 端 | 模块 | 需求内容 | 涉及页面 | 原型入口 | 待确认 |
|---|---|---|---|---|---|---|
```

入口页建议包含：

- 页面名称
- PC/移动端标识
- 页面用途
- 入口链接
- 是否待确认

## 14. 待确认问题处理

待确认问题不要丢。

处理方式：

- 影响页面结构的问题：先确认，不直接画死。
- 不影响页面结构的问题：可以先画占位，并在右侧黄色标签区标“待确认”。
- 来自竞品截图推测的字段来源、状态流转、交互结果，必须保留待确认标识。

## 最终检查

输出前检查：

- 是否包含需求说明，不是只有线框图。
- 每个页面是否来自页面内容说明，且不是空页面。
- 手机/PC线框内是否只包含真实原型页面内容。
- 红色说明文字、需求说明、规则卡片、状态示意图是否全部移到右侧黄色标签区。
- 每个可点击按钮是否有明确结果；无结果时是否标注“按钮结果待确认”。
- 跳转目标页面或弹窗是否有展示内容说明。
- 列表行按钮是否操作当前行记录，并在弹窗或目标页面中展示当前行关键字段。
- 审核、驳回、通过、标记成功等业务按钮是否使用业务弹窗或状态变化，而不是通用 alert。
- 业务弹窗是否包含标题、字段区、取消/确认按钮、确认后结果和取消后结果。
- 是否没有在线框内使用红字说明。
- 右侧黄色标签区是否覆盖字段级、按钮级、列表级、状态级、页面级规则和复杂规则。
- 同一页面是否只默认展示一个互斥状态，状态示意图和全部状态是否在右侧黄色标签区讲清楚。
- 目录导航是否体现入口、端、模块、页面、弹窗的层级关系，且没有把状态放进左侧导航。
- 有业务动作、字段、按钮结果或状态变化的业务弹窗是否已进入左侧导航，并放在所属页面下级。
- 弹窗目录节点是否能先进入所属页面，再打开对应弹窗。
- 目录导航是否优先使用需求分析的页面层级树；如果是推断层级，是否标注待确认。
- 字段是否来自需求分析输入。
- 按钮是否说明点击结果。
- PC/移动端差异是否明确。
- 页面跳转是否清楚。
- 待确认问题是否保留。
