# 需求原型合并规范

## 主入口与兼容入口

- `requirements-to-axure-html-prototype` 是需求到 Axure 风格 HTML 原型的主流程入口。
- `requirement-analysis` 只做需求分析，不生成原型；产出必须能交给主入口或 `axure-prototype-design` 继续使用。
- `axure-prototype-design` 只在已有结构化需求分析或 **原型设计输入** 时使用；输入不足时先回到需求分析。
- 原型反馈、旧 Axure 复用、黄色说明区、页面跳转、弹窗、状态和 HTML 可点击交付统一由主入口收口。

## 需求分析保留内容

需求分析必须保留这些交付块：

1. 背景与范围
2. 业务规则
3. 字段说明
4. 功能按钮与操作说明
5. PC/移动端差异
6. 页面内容说明
7. 页面与跳转逻辑
8. 待确认问题
9. 原型设计输入

字段、按钮、页面和状态必须可追溯。无法确认的字段来源、权限、跳转、状态结果、PC/移动范围和弹窗内容放入 **待确认问题**，不要静默补全。

## 原型设计保留内容

Axure 风格原型必须保留这些约束：

- 页面层级先于页面绘制，页面归属、模块、子页面、详情页、业务弹窗不能被压平成一层列表。
- 线框图区域只放用户真实可见 UI。
- 右侧黄色说明区放业务规则、字段来源、按钮结果、权限、状态、待确认问题、变更记录和评审说明。
- 业务弹窗如果有独立字段、规则、按钮结果、状态变化或审批/启停/确认含义，必须作为所属页面或模块下的可发现节点。
- 按钮必须有结果：跳转、弹窗、保存、刷新、返回、状态变化、隐藏/禁用，或明确标为待确认。

## 反馈闭环

原型反馈先分类再修改：

- 业务规则、字段、按钮、状态、权限、跳转变更：同步更新需求分析和原型输入。
- 页面布局、弹窗内容、黄色说明区、点击行为：更新原型计划或 HTML。
- 纯视觉间距、颜色、文案微调：可只改原型，但记录“需求无影响”。

每轮反馈至少记录：反馈点、分类、需求影响、原型影响、影响页面/文件、处理结果、待确认问题。
