# 高保真原型说明

## 背景

本轮将领榜教育家长端和教师端从现有合并/联动原型中拆分为两个可独立打开的 HTML 原型，便于分别评审端内页面、导航、mock 数据和交互状态。

## 目标

- 产出家长端和教师端两个独立 HTML 文件。
- 保留源原型对应端的页面、端内导航、mock 数据、交互状态和标注说明。
- 移除领榜后台、优坐标端、六端切换、iframe 内嵌和家长/教师跨端切换依赖。
- 验证桌面端和移动端首屏、核心导航与主要端内路径。

## 关键结论

本任务分类为“已有原型拆分/迁移”。采用对应源文件复制后定向裁剪：家长版固定 `parent` 状态并保留家长导航；教师版固定 `teacher` 状态，仅保留教师导航；两版保留原有手机端页面、底部导航、mock 数据、弹窗/抽屉/提示和交互式标注工具。标注 JSON 仅保留当前端 `surface` 数据。

## 交互规则

| 操作 | 反馈 |
| --- | --- |
| 点击端外层导航 | 切换当前端内页面并同步导航高亮、页面状态和标注 |
| 点击底部 Tab | 切换首页/教师/订单/我的等端内主页面，滚动位置回到页面顶部 |
| 点击卡片、订单、教师 | 进入对应详情或列表，并携带源原型 mock 数据 |
| 点击保存、申请、评价、联系客服等操作 | 依据源原型显示弹窗、toast、状态变更或详情页 |
| 点击新增标注 | 进入标注放置模式，支持查看、编辑、删除、搜索和 JSON/HTML 导入导出 |

## 状态说明

- 默认态：家长端首页；教师端最新家教订单。
- 业务态：待接单、已申请、进行中、已完成、已取消等订单状态。
- 空状态：无待接单订单、暂无老师报名等源原型已有空状态。
- 异常/反馈态：保存失败、操作提示、联系客服、无匹配结果等源原型已有反馈。
- 加载/异步态：保留源原型中按钮反馈和模拟刷新表现；不接入真实接口。
- 标注态：默认显示当前端且匹配当前页面的标注，支持隐藏和编辑。

## 权限差异

本轮仅保留端内角色边界，不新增角色模型。家长端只展示家长资料、需求和订单操作；教师端只展示教师资料、接单和教师订单操作。后台审核、财务、优坐标端权限不在两个独立原型中提供。

## 数据刷新逻辑

页面切换使用源文件中的本地 mock 数据重新渲染；订单 Tab、学段/学科筛选、教师详情和订单详情按当前端状态更新。刷新结果只存在于当前浏览器页面和 localStorage 标注数据中，不代表真实后端数据。

## mock 数据说明

mock 数据直接承接两份源 HTML 内的教师资料、订单、用户资料、课程/学科、海报二维码和状态样例；拆分只裁剪端身份和标注，不改写业务字段，不视为生产数据。

## 响应式差异

桌面尺寸展示手机原型与对应端外层导航；宽度较小时隐藏外层导航，保留手机原型和标注工具，以避免导航遮挡业务内容。该差异沿用源原型的移动端规则，两个新文件均可独立加载，不依赖跨端页面。

## 待确认问题

- 家长端和教师端后续是否需要分别维护独立版本号，而不是由合并原型统一递增。
- 教师端是否需要补充独立的教师首页，当前沿用源原型的“最新家教订单”作为首屏入口。
- 真实接口、登录态、支付和权限校验仍需后续数据交互与需求文档确认。

## 风险与依赖

- 两份源 HTML 体积较大且包含内嵌图片，后续编辑需避免破坏 base64 资源和脚本边界。
- 当前数据仍为离线 mock，浏览器刷新不会模拟真实后端一致性。
- 标注工具支持本地 localStorage；不同文件使用同一工具存储键时，需避免在同一浏览器中混用旧版标注数据。
- 源原型中部分页面仍按共享页面结构存在，但入口和导航已按端拆分；若要物理删除所有非当前端隐藏页面，需要上游确认页面范围后再做下一版裁剪。
