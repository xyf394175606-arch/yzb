# 高保真原型_优坐标老师列表教师类型标签调整说明_v2_20260705

## 背景

本轮基于“全部老师”列表页评审反馈，对教师类型筛选和老师卡片身份展示进行调整。原型上一版中，“硕博教员 / 骨干教员 / 专业教员”在卡片头像底部同层展示，容易让用户理解为三类并列老师类型。本轮按评审意见，将“硕博”从主类型中拆出，作为骨干老师下的学历/资质角标展示。

## 目标

- 将前台老师类型筛选调整为“骨干老师 / 专业老师”两类。
- 将“硕博”改为头像右上角角标，不再作为头像底部主身份。
- 同步调整 PC 后台教师管理字段，避免后台仍把“硕博教师”作为同层教师类型。
- 保留 3 个筛选项方案作为待确认备选，而不直接画入当前推荐线框。

## 关键结论

- 本轮推荐方案已落入 HTML 原型：前台采用 2 个老师类型筛选，即“骨干老师 / 专业老师”。
- 硕博老师不再作为同层主类型展示；具备硕博身份的骨干老师在头像右上角展示“硕博”角标。
- PC 后台教师类型只保留“骨干教师 / 专业教师”，另增“硕博标识”字段。

## 待确认问题

- 前台对外称呼最终统一使用“老师”还是继续保留“教员”？当前原型保留姓名如“袁教员”，但类型文案已先改为“老师”。
- 顶部筛选最终是否采用当前推荐的 2 个选项；若业务坚持 3 个选项，需要确认“硕博老师”是独立类型还是骨干老师子筛选。
- “硕博标识”是否只允许骨干老师拥有，还是专业老师也可能拥有。
- “骨干老师”的业务定义是否需要在前台给用户轻量解释。

## 风险与依赖

- 如果后台数据仍按“硕博教师 / 骨干教师 / 专业教师”三类维护，则前台 2 类筛选与后台配置会不一致。
- 如果前台继续混用“老师 / 教员”文案，用户对类型、身份和称呼的理解可能不够统一。
- 若业务后续要求“硕博老师”可单独筛选，需要补充筛选逻辑：选择骨干老师是否包含硕博，选择硕博是否只筛骨干老师中的硕博子集。

## 下一步动作

- 产品侧确认老师类型筛选最终采用 2 个还是 3 个选项。
- 设计侧可基于 v2 HTML 继续细化“硕博”角标视觉大小、位置和颜色。
- 数据交互阶段需补齐“教师类型”和“硕博标识”的字段来源、筛选参数和后台保存规则。
