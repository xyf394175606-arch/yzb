## 已确认业务规则

### 全部老师列表

- 筛选项为年级、学科、教员类型和综合排序。
- 年级、学科来自数据字典；教员类型来自教师类型维护，支持一级与二级类型。
- 任一筛选条件或排序变化后立即刷新老师卡。
- 无老师符合筛选条件时，自动展示全部老师，并保留当前综合排序规则。
- 综合按前端展示顺序从大到小；评分、授课时长、收藏人数均先按对应统计从高到低，相同值再按前端展示顺序从大到小。
- 多个授课年级在老师卡中按高中、初中、小学的优先级归并展示；多个授课学科展示第一个已选学科。
- 毕业院校与最高学历分别通过各自展示开关控制：均勾选时组合展示，只勾选一项时仅展示该项，均不勾选时隐藏学历信息。
- 只有已上架、未作废且允许前台展示的老师进入前台列表。

### 教师详情页

- 展示顺序为教师头部、适合这样的孩子、老师介绍、教学成果、提分案例、家长评价、购买课程、咨询顾问底栏。
- 顶部锚点为老师介绍、家长评价、购买课程。
- 所在区域只展示省、市、区县，不展示详细地址；没有区域时不占位。
- 适合这样的孩子由广告位维护，整组开关默认关闭；开启后展示已启用的条目。
- 教师简介有内容即展示，最多 200 字；主讲科目最多选择 5 个，未选择时隐藏。
- 教学成果由系统默认展示。授课时长和家长评分来自统计，提分率来自页面展示资料。
- 提分案例使用主标题、副标题、强化副标题、Icon 和展示状态；隐藏条目不在前台展示。
- 家长评价只读取评价汇总和前台可见的评价内容；隐藏评价仅影响前台内容，不影响评分、星级分布或评价数量。
- 购买课程只展示已关联、可售且允许前台展示的课程。
- 咨询顾问未关联、资料不完整、不可用或关闭展示时，隐藏顾问底栏、电话和在线咨询入口。

### 后台编辑教师与数据来源

| 前台内容 | 后台维护来源 | 控制规则 |
| --- | --- | --- |
| 头像、教师名称、性别、区域、年级、学科 | 基本认证资料、认证图片资料 | 区域可暂不填写，但上架或开启前台展示前必须补齐。年级和学科可多选。 |
| 一级与二级教师类型 | 教师类型维护、编辑教师中的类型选择 | 二级类型非必填；有二级类型时前台展示对应标识。 |
| 教学经验、展示姓名、简介、主讲科目、虚拟收藏人数 | 页面展示资料 | 保存后刷新前台对应模块。 |
| 授课时长、基础收藏人数、家长评分 | 业务统计、评价汇总 | 只读统计，不在编辑教师页面手工修改。前台收藏人数为基础收藏人数与虚拟收藏人数之和。 |
| 适合这样的孩子、提分案例 | 页面展示资料中的广告位与教学成果 | 由总开关、单条展示状态和完整资料共同控制。 |
| 课程 | 关联课程、课程管理 | 不在教师资料中重复维护。 |
| 顾问资料 | 咨询顾问维护 | 一个顾问可关联多个老师；一个老师只允许关联一个顾问。 |

### 后台教师列表

- 列表字段固定为：教师姓名与脱敏手机号、性别、年级、学科、教师类型、主讲科目、教学经验、授课时长、收藏人数、关联课程数、展示状态、审核状态、最近更新时间和操作。
- 操作顺序为：查看、编辑、下架或上架、作废、全部评价、关联课程、排序。
- 前端展示排序不在编辑教师弹窗维护。默认范围用于未选择教师类型的列表；选择一级或二级类型时，使用该类型范围的独立排序；数值越大越靠前。

### 教师类型、标签与关联规则

- 首页 Icon 入口只由一级教师类型配置；二级类型明确为不配置首页入口。
- 一级类型开启首页展示后，首页展示主标题、副标题、Icon 图片和首页 Icon 排序均为必填。首页展示条件为：一级类型启用、允许前台展示、首页展示开启且配置完整。
- 首页 Icon 按首页 Icon 排序从大到小展示，不复用教师类型内部排序或老师前端展示排序；点击后进入对应一级类型的独立活动页。
- 活动页只展示一级类型匹配、已上架、未作废、允许前台展示且已配置该类型排序的老师。
- 教师类型和教师标签列表均展示关联老师数量，并提供“查看关联教师”。关联列表展示登录手机号、姓名和修改关联操作。
- 修改教师类型关联时必须选择替换的一级类型；二级类型非必填。确认后立即生效并刷新关联数量，不提供直接取消关联导致老师无类型的状态。
- 教师标签禁用后不可新选；已经关联的历史标签按现有数据展示，具体清理由运营另行处理。

### 评价、课程与顾问关联规则

- 全部评价的隐藏或展示仅控制该条评价在教师详情页的可见性，不删除后台记录，不改变评分、星级分布和评价总数。
- 课程由平台课程管理创建，再通过“关联课程”关联至老师；老师未关联可售课程时不可上架。
- 咨询顾问在独立维护页统一维护头像、姓名、电话、微信状态和在线咨询会话标识；编辑教师页面不维护顾问资料，仅在关联入口选择一个顾问。
- 一个咨询顾问可关联多位老师；一位老师仅能关联一位咨询顾问。更换关联后详情页的顾问底栏立即读取新顾问资料。

## 原型交互与修改约定

- 这是既有原型迭代，保留现有页面、模拟数据、交互结果和右侧黄色需求说明；仅改动已确认的业务范围。
- 修改前台或后台字段时，必须同时更新：页面展示、保存联动、右侧黄色需求说明和本交付文档或原始需求变更说明。
- 任何配置类弹窗底部默认只保留“取消、保存”；删除放在列表或表格行内，除非另有明确需求。
- 不接真实接口、行政区字典、图片存储、电话或即时通信服务；本轮均为可评审原型。
- 原型内使用模拟数据。新增展示字段时，不可只在前台写死，必须有对应后台维护来源或业务统计来源。

## 发布流程

1. 在 `_new_teache_20260718` 分支修改、检查并提交。
2. 推送新版分支：

```bash
git push origin _new_teache_20260718
```

3. 需要更新公开网页时，先拉取并合并最新 `main`，处理冲突后再将已验证版本发布到 `main`。GitHub Pages 当前只监听 `main`。

```bash
git fetch origin main
git merge origin/main
git push origin _new_teache_20260718
git push origin _new_teache_20260718:main
```

4. 等待 GitHub Actions 的“Deploy static content to Pages”完成后，再访问在线原型地址验证目标页面返回成功。

- GitHub Pages 只从 `main` 发布，继续开发应始终在新版分支完成后再发布。
