# 分销模块规则优化最终 PRD（页面说明版）

## 方法参考说明

本文按 `prd-writer` 的 PRD、User Story、优先级和验收案例方法整理，业务规则以分销模块需求分析 v24、原型 v25、数据交互契约 v1 和用户最新确认内容为准。本文补充逻辑数据契约，但不扩展数据库表结构、完整 OpenAPI 或自动结算能力。

## 背景

当前分销需求已经形成创客中心、提现和 PC 后台原型，但原有描述容易把“注册行为、邀请关系、销售行为、课程课消、会员激活、老师课时收入”混在一起。研发和测试需要一份以业务事件为中心的规则文档，明确谁因什么事件、按哪一层级、使用哪一类比例获得哪一笔分润。

## 目标

- 固化二级分销关系和五类分润来源的归属、触发和计算口径。
- 将同一业务事件的多来源收益拆开记录，避免邀请方、销售方和老师个人收益重复或错配。
- 将规则停用、规则版本、重复事件、无邀请、超二级和退款撤销等边界转化为可执行验收案例。
- 让分销比例配置、分润明细、提现和创客中心展示使用同一套“分润”口径。

## 关键结论

1. 本版本是二级分销：直接邀请关系为一星，间接邀请关系为二星，三级及以上不产生分润。
2. 分润来源固定为：家长注册、销售课程、购买会员、老师注册、课时分润。原“上课”不再作为配置来源名称。
3. 家长注册和老师注册是“关系来源分润”；销售课程和购买会员是“销售来源分润”；课时分润是“老师课时事件产生的关系分润”。
4. 老师个人课时收入不是分销分润，不能发给老师的上级，也不能并入课时分润记录。
5. 课程和会员业务在确认前可以生成待确认口径的分润记录，但不可计入可提现金额；课程以课消确认后的实付金额为计佣基数，会员以激活使用后的实付金额为计佣基数。
6. 同一业务事件可以产生多条不同来源记录，但同一来源、同一业务事件只能计算一次。
7. 保存配置后即时影响新事件；用户绑定关系时固化规则版本，已绑定用户沿用绑定时规则，新绑定用户使用最新规则。
8. 退款、撤销、课消取消本期不自动扣回，转人工处理；自动打款、自动退款扣回、三级及以上分销不属于本版本。

## 规则总览

### 1. 关系层级规则

| 关系 | 定义 | 使用比例 | 允许分润 |
| --- | --- | --- | --- |
| 一星 | A 直接邀请 B，A 是 B 的直接邀请方 | 一星比例 | 是 |
| 二星 | A 邀请 B，B 再邀请 C，A 是 C 的间接邀请方 | 二星比例 | 是 |
| 三级及以上 | 超过两层的上级关系 | 无 | 否 |
| 无邀请 | 用户没有系统内有效邀请关系 | 无关系比例 | 否；销售方仍可按销售来源计佣 |

### 2. 分润来源规则

| 来源 | 触发事件 | 计佣基数 | 分润获得人 | 不触发条件 |
| --- | --- | --- | --- | --- |
| 家长注册 | 被邀请家长完成首笔销售课程或购买会员并达到确认条件 | 后台运营配置为固定金额或固定比例，二选一；按当前配置模式计算 | 一星/二星邀请关系方 | 仅注册、无邀请、业务未确认 |
| 老师注册 | 被邀请用户确认注册成为老师 | 按当前老师注册一星/二星配置 | 一星/二星邀请关系方 | 注册未确认、超二级 |
| 销售课程 | 课程课消确认 | 确认后的实付金额 | 课程销售方 | 课消未确认、重复事件 |
| 购买会员 | 会员激活使用 | 激活后的实付金额 | 会员销售方 | 未激活、重复事件 |
| 课时分润 | 老师完成课时并确认产生课时收入 | 按当前课时分润配置 | 老师的一星/二星邀请关系方 | 课时未确认、超二级 |

### 3. 多来源拆分规则

- 邀请关系方因家长注册或老师注册获得关系来源分润。
- 会员销售方因购买会员获得销售来源分润。
- 课程销售方因销售课程获得销售来源分润。
- 老师本人获得个人课时收入；其上级另按课时分润来源获得分润。
- 同一用户同时是邀请方和销售方时，按来源分别计算、分别记录，不合并为一条。
- 试听课和会员是两个业务事件，必须分别计算、分别记录。

### 5. 家长注册金额配置规则

家长注册来源由后台运营配置计算模式，模式为二选一，且同一来源同一时刻只允许使用一种模式：

| 配置模式 | 配置内容 | 计算方式 | 互斥规则 |
| --- | --- | --- | --- |
| 固定金额 | 一星固定金额、二星固定金额 | 对达到确认条件的家长注册事件，按对应层级直接发放配置金额 | 不再叠加比例 |
| 固定比例 | 一星比例、二星比例 | 以该事件确认金额为基数，按对应层级比例计算 | 不再叠加固定金额 |

后台保存时必须明确当前模式；未选择模式、固定金额为空、比例格式非法或同时启用两种模式时不得保存。

### 4. 规则版本与启停

- 分销比例配置不再配置生效时间字段。
- 保存比例后对后续业务事件即时生效。
- 用户建立绑定关系时记录当时规则版本；已绑定关系继续使用绑定时版本。
- 新绑定关系使用最新版本。
- 停用某来源只阻止该来源的后续事件，不修改已产生记录。
- 不设置单笔订单、单个来源或总佣金封顶。

## 分润计算流程

```text
业务事件发生
  ↓
判断事件是否达到确认条件
  ├─ 否 → 记录为待确认/不生成可提现分润
  └─ 是
      ↓
识别业务来源（注册/课程/会员/老师注册/课时）
      ↓
读取被绑定关系的规则版本
      ↓
识别一星、二星关系
      ├─ 无邀请 → 不生成关系来源分润；若有销售方，继续计算销售来源
      ├─ 一星 → 按一星比例生成一笔来源记录
      ├─ 二星 → 按一星和二星比例分别生成对应记录
      └─ 超二级 → 不生成三级及以上记录
      ↓
判断同一来源、同一业务事件是否已处理
  ├─ 是 → 幂等返回，不重复生成
  └─ 否 → 生成分润记录并进入已确认/可提现口径
```

## 状态机

### 分润记录状态

| 状态 | 进入条件 | 退出条件 | 用户可见表现 |
| --- | --- | --- | --- |
| 待确认 | 课程未完成课消确认或会员未激活，且已形成对应分润候选记录 | 达到确认条件转为已确认，或进入人工处理 | 可展示在待确认金额/待确认分润口径，但不可计入可提现金额 |
| 已确认 | 业务确认且规则、关系有效 | 被提现锁定或进入异常人工处理 | 计入分润明细和可提现口径 |
| 已锁定 | 用户提交提现，余额被锁定 | 提现完成、驳回或作废处理 | 可提现金额扣除锁定金额 |
| 已处理 | 分润已进入提现结果或人工结案 | 无 | 保留历史记录 |
| 人工处理 | 退款、撤销、课消取消等本期不自动处理 | 后台人工完成 | 不自动生成冲正记录 |

### 提现状态

| 状态 | 进入条件 | 退出条件 | 用户可见表现 |
| --- | --- | --- | --- |
| 审核中 | 提现申请提交成功 | 审核通过或驳回 | 金额锁定，不允许再次提交 |
| 已驳回 | 后台驳回且填写原因 | 用户重新满足条件后发起新申请 | 展示驳回原因 |
| 待打款 | 后台审核通过 | 财务标记已打款 | 展示待打款 |
| 已打款 | 财务确认系统外打款 | 异常时作废 | 展示已打款 |
| 已作废 | 对已打款记录执行作废 | 无 | 保留原记录和作废原因 |

## 分润记录模型

### 1. 记录生成规则

| 业务阶段 | 是否生成分润记录 | 记录状态 | 是否进入待确认口径 | 是否进入可提现金额 |
| --- | --- | --- | --- | --- |
| 课程发生购买/产生销售事件，但尚未完成课消确认 | 是，生成候选记录 | `pending_confirmation` | 是 | 否 |
| 会员购买完成，但尚未激活使用 | 是，生成候选记录 | `pending_confirmation` | 是 | 否 |
| 课程完成课消确认 | 更新原候选记录 | `confirmed` | 否，转为已确认 | 是 |
| 会员完成激活使用 | 更新原候选记录 | `confirmed` | 否，转为已确认 | 是 |
| 老师注册确认完成 | 直接生成确认记录 | `confirmed` | 否 | 是 |
| 老师课时确认完成 | 生成确认记录 | `confirmed` | 否 | 是 |
| 退款、撤销、课消取消 | 不生成自动扣回记录 | 保留原状态 | 保留原待确认/已确认记录 | 不自动调整 |

### 2. 分润记录字段

| 字段 | 含义 | 待确认状态 | 已确认状态 |
| --- | --- | --- | --- |
| 业务事件编号 | 关联注册、课程、会员或课时业务事件 | 必填 | 不变 |
| 分润来源 | 家长注册、销售课程、购买会员、老师注册、课时分润 | 必填 | 不变 |
| 受益人 | 实际获得该条分润的用户 | 已根据关系或销售方确定 | 不变 |
| 分润层级 | 一星、二星或销售方/老师本人 | 已确定 | 不变 |
| 业务金额 | 订单或课时业务金额 | 可为空或为业务预估值，不作为可提现金额 | 使用确认后的实付金额/确认金额 |
| 分润金额 | 按规则计算出的金额 | 可展示为待确认分润金额 | 转为已确认分润金额 |
| 分润状态 | 记录当前确认状态 | `pending_confirmation` | `confirmed` |
| 可提现标识 | 是否进入可提现汇总 | `false` | `true`，被提现后按锁定状态处理 |
| 规则版本 | 计算该记录使用的规则版本 | 绑定关系确定后写入 | 不允许被当前最新配置覆盖 |

### 3. 金额汇总规则

```text
待确认金额 = status 为 pending_confirmation 的分润金额合计
可提现金额 = status 为 confirmed 且未被锁定/已处理的分润金额合计
提现可申请金额 = 可提现金额 - 当前锁定金额
```

- 待确认金额可以在创客中心首页和分润明细中展示，但不得参与最低提现金额判断。
- 提现申请只读取可提现金额，不读取待确认金额。
- 业务确认完成后，原待确认记录更新为已确认记录，不重复生成第二条同来源分润记录。
- 如果确认事件重复到达，按业务事件编号幂等处理，保持一条记录和一个分润结果。

### 4. 页面展示规则

| 页面 | 待确认记录展示 | 可提现记录展示 | 禁止行为 |
| --- | --- | --- | --- |
| 创客中心首页 | 展示待确认金额，使用“待确认”标签 | 展示可提现金额 | 待确认金额不得与可提现金额相加后用于提现 |
| 成员详情-分润明细 | 展示来源、业务事件、分润金额和“待确认”状态 | 展示来源、金额和已确认状态 | 不将待确认记录展示为可提现分润 |
| 提现中心 | 可展示待确认金额作为说明 | 只展示可提现金额、锁定金额和最低提现金额 | 不允许使用待确认金额申请提现 |
| 后台分润查询 | 可按待确认/已确认筛选 | 可按已确认、已锁定等状态筛选 | 不得通过前端修改确认状态 |

## 功能详细说明

### 功能一：分销规则配置

**功能描述**

运营人员在 PC 分销比例配置页维护五类分润来源。家长注册必须先选择固定金额或固定比例，其他来源配置一星/二星比例。保存成功后影响后续业务事件，并写入历史版本。

**用户流程**

```text
进入分销比例配置
  ↓
编辑家长注册模式和值，或编辑其他来源比例
  ↓
点击保存配置
  ├─ 保存成功 → 提示“配置已保存并即时生效”，刷新当前配置和历史记录
  ├─ 未选择模式 → 提示“请选择家长注册分润计算模式”，停留页面
  ├─ 金额/比例非法 → 提示“请输入合法的固定金额/比例”，阻止保存
  └─ 网络或权限失败 → 保留输入，提示“配置保存失败，请重试”
```

**状态机与字段**

| 状态 | 进入条件 | 用户可见表现 |
| --- | --- | --- |
| 编辑中 | 修改任一模式或值 | 保存按钮可用，显示当前输入 |
| 保存中 | 点击保存并通过前端校验 | 保存按钮禁用，显示加载状态 |
| 已保存 | 后端保存成功 | 显示成功提示，新增历史版本 |
| 保存失败 | 后端拒绝或网络失败 | 保留输入，显示错误 |

| 字段 | 必填 | 校验 |
| --- | --- | --- |
| 家长注册计算模式 | 是 | `fixed_amount` / `fixed_ratio` 二选一 |
| 家长注册一星/二星值 | 是 | 固定金额模式为金额且不小于 0；固定比例模式为 0%-100% |
| 其他来源一星/二星比例 | 是 | 0%-100%，可为 0 |

### 功能二：分润事件处理

**功能描述**

系统接收注册、课程、会员和课时业务事件，先建立业务事件与关系快照，再按来源拆分受益人记录。课程课消确认和会员激活前只形成待确认记录，不进入可提现金额。

**用户流程**

```text
接收业务事件
  ↓
校验 event_id 和事件类型
  ├─ 重复事件 → 返回原处理结果，不新增记录
  └─ 新事件
      ↓
判断确认条件
      ├─ 未确认 → 生成 pending_confirmation，不进入可提现金额
      └─ 已确认 → 继续匹配规则和关系
          ↓
      读取绑定时规则版本并识别一星/二星
          ├─ 无邀请 → 不生成关系分润，销售方按销售来源独立计算
          ├─ 一星/二星 → 生成对应来源记录
          └─ 三级及以上 → 截断，不生成三级记录
```

**关键规则**

- `event_id` 相同的同一来源事件只处理一次。
- 课程/会员未确认时允许记录候选金额，但 `可提现标识=false`。
- 确认事件到达后更新原待确认记录为 `confirmed`，不新建重复记录。
- 退款、撤销、课消取消不生成自动扣回记录。

### 功能三：分润记录查询

**功能描述**

用户在成员详情的分润明细中查看当前成员本人直接分润；创客中心展示待确认金额和可提现金额，但两者必须分开。

**用户流程**

```text
进入成员详情-分润明细
  ↓
查询当前成员直接分润记录
  ├─ 无记录 → 展示“暂无分润记录”
  ├─ 待确认 → 展示来源、金额和“待确认”标签，不计入可提现金额
  └─ 已确认 → 展示来源、金额和“已确认”标签，计入可提现金额
```

**展示字段**

| 字段 | 展示规则 |
| --- | --- |
| 分润来源 | 展示家长注册、销售课程、购买会员、老师注册、课时分润 |
| 业务事件 | 展示课程、会员、注册或课时事件摘要和事件时间 |
| 分润金额 | 待确认记录展示待确认金额；已确认记录展示确认后金额 |
| 分润状态 | `待确认`、`已确认`、`已锁定`、`已处理` |
| 可提现标识 | 待确认显示否；已确认且未锁定显示是 |

**异常处理**

| 异常 | 处理 |
| --- | --- |
| 加载失败 | 提示“分润明细加载失败，请重试”，保留页面入口 |
| 无权限 | 提示“当前账号暂无分销权限”，不返回分润数据 |
| 只有待确认记录 | 展示记录和待确认金额，明确“暂不可提现” |
| 只有已确认记录 | 展示可提现口径金额，允许进入提现资格判断 |

### 功能四：提现申请与处理

**功能描述**

用户只能使用已确认且未锁定的可提现分润申请提现。提交时校验金额、最低提现金额、短信验证码和未完成申请；提交成功后立即锁定金额。

**用户流程**

```text
进入提现中心
  ↓
查看可提现金额、待确认金额和锁定金额
  ↓
点击申请提现
  ├─ 可提现金额低于最低金额 → 按钮置灰，提示最低提现金额
  ├─ 存在未完成申请 → 禁止进入申请页
  └─ 条件满足 → 填写金额、收款信息和短信验证码
      ↓
      提交申请
      ├─ 成功 → 申请进入审核中，金额立即锁定
      ├─ 金额非法 → 停留本页并提示金额错误
      ├─ 验证码错误 → 停留本页并提示验证码错误
      └─ 网络失败 → 保留填写内容，允许重试
```

**后台处理流程**

```text
审核中
  ├─ 审核通过且备注非空 → 待打款
  ├─ 驳回且驳回原因非空 → 已驳回，释放锁定金额
待打款
  └─ 打款备注非空 → 已打款
已打款
  └─ 作废原因非空 → 已作废，不做自动冲正
```

| --- | --- | --- |

| 申请表单 | 提现金额、收款信息、当前手机号、短信验证码 | 金额只能从可提现金额中申请 |
| 提现记录 | 申请单编号、申请金额、状态、处理结果 | 一笔未完成申请期间不可重复提交 |

**操作路径**

<div style="color:#1f5fbf;font-weight:700">进入提现中心 → 判断可提现金额 → 填写金额和收款信息 → 获取验证码 → 提交 → 锁定金额 → 进入审核中</div>

| 异常场景 | 页面反馈 | 是否允许提交 |
| --- | --- | --- |
| 可提现金额低于最低金额 | “提现金额未达到最低金额” | 否 |
| 只有待确认金额 | “待确认分润暂不可提现” | 否 |
| 已有未完成提现 | “已有提现申请处理中” | 否 |
| 验证码错误或失效 | “验证码错误或已失效” | 否 |
| 提交成功 | “提现申请已提交，对应金额已锁定” | 已提交 |

<span style="color:#c00000;font-weight:700">页面 04｜后台提现处理</span>

**页面目标**：让后台按提现状态完成审核、驳回、标记打款和作废。

| 当前状态 | 可用操作 | 必填内容 | 操作结果 |
| --- | --- | --- | --- |
| 审核中 | 审核、驳回 | 审核备注；驳回原因 | 待打款或已驳回 |
| 待打款 | 标记打款成功 | 打款备注 | 已打款 |
| 已打款 | 作废 | 作废原因 | 已作废，不自动冲正 |
| 已驳回 | 无当前申请处理操作 | 已保存驳回原因 | 用户查看驳回结果 |

**操作路径**

<div style="color:#1f5fbf;font-weight:700">进入后台提现申请 → 查看申请单 → 按状态选择操作 → 填写必填备注/原因 → 确认 → 更新状态并写入操作日志</div>

**页面验收重点**

- 审核备注、打款备注、作废原因为空时，确认按钮不可完成操作。
- 备注超过 200 字时，页面提示错误且保留弹窗输入内容。
- 已打款记录不可撤销更正，只能作废。
- 退款、撤销、课消取消不在本页面生成自动扣回操作。

## 数据与接口需求

本版本固化页面与业务数据契约，不补写具体接口名、数据库字段或后端实现。以下逻辑场景是本 PRD 的实现约束：

| 场景 | 触发动作 | 必须支持的业务数据 | 权限/校验 | 前端展示 |
| --- | --- | --- | --- | --- |
| 关系解析 | 注册、购买、老师注册、课时确认事件 | 事件用户、邀请链、层级、一星/二星关系 | 只解析系统内有效绑定 | 生成对应来源案例结果 |
| 分润计算 | 业务确认事件 | 来源、事件唯一标识、确认金额/课时、规则版本、受益人、层级 | 同来源同事件幂等 | 分润明细和金额 |
| 规则读取 | 保存/启停配置 | 五类来源、一星比例、二星比例、启停、版本 | 配置权限；比例格式校验 | 配置即时反馈、历史版本 |
| 提现提交 | 用户确认提现 | 用户、金额、收款信息快照、手机号、验证码 | 创客权限、最低金额、余额、未完成申请 | 锁定金额和审核中状态 |

### 数据契约补充

| 数据对象 | 必须字段 | 规则 |
| --- | --- | --- |
| 分润规则 | `source`、`mode`、`first_value`、`second_value`、`status`、`version` | 家长注册的 `mode` 为 `fixed_amount` 或 `fixed_ratio` 二选一；其他来源使用比例模式 |
| 分润事件 | `event_id`、`event_type`、`user_id`、`confirmed_amount`、`relation_snapshot` | `event_id` 全局唯一；课程/会员使用确认后的实付金额；关系快照包含一星、二星和绑定时规则版本 |
| 分润结果 | `event_id`、`source`、`beneficiary_id`、`level`、`amount`、`rule_version`、`status` | 不同来源分别记录；同来源同事件同受益人同层级幂等 |
| 提现申请 | `application_no`、`amount`、`status`、`locked_amount`、收款信息快照 | 提交后原子锁定余额；同一用户只能有一笔未完成申请 |
| 后台处理 | `operator`、`operated_at`、`remark`/`void_reason` | 审核备注、打款备注和作废原因均必填；备注最长 200 字 |

### 数据错误状态

| 错误状态 | 触发条件 | 前端表现 | 后端处理 |
| --- | --- | --- | --- |
| `RULE_MODE_REQUIRED` | 家长注册未选择计算模式 | “请选择计算模式” | 拒绝保存 |
| `RULE_VALUE_INVALID` | 固定金额或比例非法 | “请输入合法的固定金额/比例” | 拒绝保存 |
| `EVENT_DUPLICATED` | 同一来源同一事件重复上报 | “该业务事件已处理，不重复生成分润” | 返回原处理结果 |
| `WITHDRAW_PENDING_EXISTS` | 已存在未完成提现申请 | “已有提现申请处理中” | 拒绝创建第二笔 |
| `REQUIRED_REMARK` | 备注或作废原因为空 | “请填写备注/作废原因” | 不更新提现状态 |

## 验收标准

| 验收对象 | 类型 | 验收标准 |
| --- | --- | --- |
| 关系层级 | 功能 | A->B 只产生 A 一星；A->B->C 产生 B 一星和 A 二星；不产生三级 |

| 多来源 | 规则 | 邀请方、销售方、老师收益可同时存在且分别记录 |
| 幂等 | 异常 | 同来源同业务事件重复回调不重复生成记录 |
| 版本 | 数据 | 已绑定关系使用绑定时规则版本，新绑定关系使用最新版本 |
| 停用 | 数据 | 停用只影响后续事件，不修改历史记录 |
| 提现 | 功能 | 提交后余额锁定；低于最低金额、余额不足或已有未完成申请时不能提交 |
