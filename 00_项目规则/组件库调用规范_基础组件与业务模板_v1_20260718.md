# K12 原型组件库调用规范

## 背景

当前 k12 项目以可交互 HTML 原型为主要交付物，历史原型中存在重复实现按钮、表单、表格、弹窗和导航的情况。组件库用于让 Codex 后续页面优先复用已确认的视觉与交互规则。

## 目标

- 首期统一 Web 后台高频组件。
- 用“基础组件 + 业务模板”双层索引减少页面自由发挥。
- 将颜色、字号、间距、圆角、按钮层级和基础交互状态固定下来。
- 让组件展示台成为评审、复用和版本变更的共同入口。

## 关键结论

### 1. 适用范围

首期只覆盖 Web 后台原型，不直接覆盖 App、小程序或生产 React/Vue 代码。

### 2. 双层结构

| 层级 | 职责 | 首期内容 |
| --- | --- | --- |
| 基础组件 | 提供稳定的外观、基础交互和状态 | 按钮、输入框、选择器、开关、搜索框、时间筛选、时间范围、组合筛选栏、表格、分页、标签页、进度条、状态标签、弹窗、抽屉、轻提示、加载等 |
| 业务模板 | 将基础组件组合成页面级结构 | 列表页、配置页、详情页 |

### 3. 视觉规则

- 默认主色使用 `#2563EB`，成功、警告、危险分别使用 `#10B981`、`#F59E0B`、`#EF4444`。
- 间距使用 4px 基准网格；后台正文 14px；卡片、输入框默认 8px 圆角。
- 首期只允许 K12 统一默认皮肤，不在单个页面临时修改颜色、圆角、间距或阴影。

### 4. 状态规则

基础组件首期覆盖：默认、悬停、聚焦、禁用、选中、加载。空态、错误、无权限和业务成功/失败反馈由业务模板和页面说明承接，不在每个基础组件内重复发明。

### 5. 关键交互约束

- 配置类弹窗底部默认只保留“取消”和“保存”。
- 删除默认放在所属列表的行内操作中。
- 加载优先使用与最终布局一致的骨架状态，避免布局跳动。
- 无结果、接口错误和无权限必须由页面模板明确展示，不能让组件静默失效。
- 列表搜索统一支持业务明确的关键词字段，例如名称、手机号；组件不默认猜测后端字段。
- 时间筛选同时提供常用快捷范围和自定义时间范围；结束时间早于开始时间时必须阻止查询并提示。
- 组合筛选栏展示已生效条件，并提供清空条件入口；筛选条件变化后按页面约定刷新列表结果。
- 筛选类组件统一使用“确认”和“重置”两个动作；不得在同一类筛选场景混用“搜索、查询、应用、清空条件”等同义按钮。
- 关键词筛选是组合组件，默认由关键词输入、确认、重置组成；关键词字段按页面业务配置，例如名称、手机号。
- 时间筛选由快捷范围或日期范围字段、确认、重置组成；组合筛选栏可叠加状态、关键词和时间条件，但动作仍保持确认/重置一致。
- 弹窗组件按内容复杂度分为小、中、大三种尺寸：小弹窗约 360px，用于确认和轻量操作；中弹窗约 520px，用于常规新增、编辑和配置；大弹窗约 860px，用于复杂配置、详情和多区块内容。
- 三种弹窗尺寸只改变容器尺寸和内容承载能力，不改变关闭方式、权限校验和底部操作规范；配置类弹窗底部仍为取消 + 保存。

## Codex 调用顺序

1. 读取本规范和组件展示台。
2. 判断页面属于列表页、配置页、详情页或其他已确认模板。
3. 从基础组件白名单中组合页面，不自行创造同类控件。
4. 为每个组件保留已确认的默认、禁用、选中和加载状态。
5. 新增组件或修改现有组件前，先记录为待确认项，不直接覆盖既有规范。

## 暂不纳入范围

- App 和小程序端组件。
- React/Vue/NPM 生产代码包。
- Figma 组件库同步。
- 完整空态、错误态、无权限态组件矩阵。
- 真实接口和生产数据。

## 待确认问题

- 后续是否需要建立 React/Vue 生产代码双轨。
- 是否需要为领榜蓝和优坐标紫增加主题 token。
- 是否需要把组件展示台发布为 GitHub Pages。

## 风险与依赖

- 如果后续页面绕过组件索引直接复制旧 HTML，组件库会逐渐失去约束力。
- 组件状态范围目前以基础交互为主，业务异常仍需在页面模板中单独验收。
- 组件视觉变更必须同步展示台、规范文件和受影响原型，避免多个版本口径并存。

## 下一步动作

- 在后续新原型任务启动时先读取本规范。
- 将列表页、配置页和详情页模板逐步扩展为可复制的 HTML 模板片段。
- 下一版本补充组件 ID、参数表、禁用条件和页面模板示例。
