# 原型设计规范：工作台布局与弹窗交互

## 背景

为保证后台配置类高保真原型的评审效率与交互一致性，沉淀首页装修工作台中已验证的三栏布局、需求说明、手机预览和业务弹窗规则。

## 目标

- 让业务人员同时查看配置入口、配置结果和需求规则。
- 让新增、编辑、配置弹窗具备统一的尺寸、层级、关闭和保存体验。
- 明确草稿、已发布、预览和异常状态的可见范围。
- 作为后台配置工作台的跨对话复用基线；除非需求明确提出例外，不允许只局部沿用样式或交互。

## 输入来源

- 优坐标首页改版与后台配置原型评审反馈。
- `00_项目规则/原型规则_配置弹窗底部操作_v1_20260714.md`。

## 关键结论

### 1. 桌面端工作台骨架

采用“左侧导航 + 中间工作区 + 右侧需求说明”三栏布局。

| 区域 | 定位 | 内容与规则 |
| --- | --- | --- |
| 左侧导航 | 页面与模块入口 | 展示工作台模块、相关维护入口和当前选中态；点击模块入口或模块行进入对应配置弹窗。 |
| 中间工作区 | 用户业务界面 | 展示页面标题、草稿/发布状态、模块列表、编辑操作和手机预览；不放评审说明文字。 |
| 手机预览 | 前台结果校验 | 与中间工作区并列，提供草稿/已发布切换；尺寸放大后仍需完整显示手机边框、底部导航和可滚动内容。 |
| 右侧需求说明 | 评审辅助层 | 固定展示当前页面或当前弹窗的规则，不属于用户业务界面，不嵌入手机预览或业务弹窗。 |

桌面端优先保证中间业务区、手机预览和右侧需求说明可同时阅读；窗口不足时先隐藏右侧需求说明，再收缩为单列工作区。移动端可隐藏左侧导航和右侧需求说明，但必须在原型说明中记录该差异。

### 2. 需求说明区规范

- 使用黄色或浅黄色背景，与业务界面视觉区分。
- 标题固定为“需求说明”，副标题标识当前页面、当前模块或当前配置弹窗。
- 内容按“页面目标、字段规则、展示规则、配置完整性、操作结果、状态/权限、待确认项”组织；按页面需要取用，不强制全部出现。
- 点击模块或打开弹窗时，说明区必须同步切换到对应规则。
- 需求说明区在弹窗打开时必须保持可见、可阅读，遮罩不得覆盖、模糊或降低其对比度。
- 需求说明只解释业务规则、数据来源、状态和待确认项，不描述视觉实现细节，也不放红色评审标注。

### 3. 手机预览规范

- 前台预览使用独立手机框，包含状态栏、内容滚动区和底部导航。
- 预览需支持草稿与已发布两个版本，草稿保存不影响已发布预览；发布成功后才同步已发布版本。
- 固定类前台元素，例如底部导航、悬浮关注卡，应脱离内容滚动区并保持固定位置。
- 分类标签或卡片超过一屏宽度时使用横向滑动；不压缩文字至不可读，也不换行破坏卡片节奏。
- 前台配置项关闭、隐藏或缺失时，应展示对应空状态、隐藏状态或配置不完整提示。

### 4. 配置弹窗规范

| 项目 | 默认规则 |
| --- | --- |
| 尺寸 | 桌面端默认宽度 850px、高度 1000px；小屏以视口可用宽高为上限。 |
| 结构 | 使用“固定标题区 + 可滚动内容区 + 固定操作区”三段式布局。 |
| 标题区 | 左侧显示页面标题和简短草稿提示，右侧提供关闭按钮；标题不随内容滚动。 |
| 内容区 | 仅内容区滚动，承载字段、列表、上传、标签选择和行内删除。 |
| 底部操作 | 默认只保留“取消”和“保存”；删除放在所属列表行内，遵循现有底部操作规范。 |
| 遮罩层级 | 遮罩可遮暗中间业务区，但必须位于左侧导航和右侧需求说明之下；弹窗位于遮罩之上。 |
| 关闭行为 | 仅点击遮罩空白区域、右上角关闭或底部取消时关闭；点击弹窗内部字段、标签、上传、全选/清空、保存等操作不得关闭弹窗。 |
| 保存行为 | 先校验必填、数量和格式规则；成功后写入草稿并关闭弹窗，失败时保留弹窗和用户输入并给出明确提示。 |

### 5. 模块选择与列表操作

- 侧栏入口、模块行和行内编辑图标应打开同一配置弹窗。
- 启用/停用、编辑、删除等行内操作必须阻止误触到模块行的选中或跳转行为。
- 可多选的类型或分类使用标签式复选控件；选中高亮，未选保持可点击。
- 多选区域类型较多时提供已选数量、全选和清空；全选/清空只修改弹窗临时状态，点击保存后才写入草稿，取消不修改草稿。
- 固定入口、固定数量和最小/最大数量规则应在字段旁或需求说明中明确。

### 6. 状态、反馈与权限

- 草稿、已发布、预览草稿、发布成功、发布失败、读取失败、空状态、配置不完整和无权限均需有可见反馈。
- 保存成功提示“已保存到草稿”；发布成功提示已发布版本已刷新；发布失败保留草稿并支持重试。
- 字段校验失败不关闭弹窗，错误信息应指向缺失字段或违反的数量/格式规则。
- 无权限时保留可理解的页面说明，禁用或隐藏无权操作，并在需求说明中写明权限边界。

## 复用检查清单

- [ ] 桌面端是否同时具备左侧导航、中间业务区、手机预览和右侧需求说明。
- [ ] 打开弹窗后左侧导航和右侧需求说明是否仍可读。
- [ ] 弹窗是否为固定头部、滚动内容、固定底部操作。
- [ ] 弹窗底部是否仅保留取消和保存，删除是否位于行内。
- [ ] 点击弹窗内部控件是否不会关闭弹窗。
- [ ] 草稿、已发布和前台预览是否按发布动作正确隔离。
- [ ] 横向标签和卡片是否在溢出时支持滑动。
- [ ] 390px 视图中内容、按钮和文字是否无重叠或截断。
- [ ] 是否完整套用左侧导航、中间工作区/预览、右侧黄色需求说明和弹窗层级，而非只复用其中部分视觉。
- [ ] 如有偏离尺寸、色值、布局比例或弹窗交互的地方，是否已由需求明确提出并记录为例外。

## 待确认问题

- 不同业务工作台是否都需要手机预览；无移动端结果的后台可改为结果预览或数据预览区。
- 850px x 1000px 是否作为全部后台弹窗的默认尺寸；大型数据选择器可在具体需求中申请例外。

## 风险与依赖

- 真实权限、发布接口、上传接口和状态数据接入后，原型中的 mock 反馈需要替换为对应接口状态。
- 若工作台同时存在多种预览形态，需在具体页面补充预览区宽度、缩放和断点规则。
