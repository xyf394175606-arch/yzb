# 需求分析稿：个人中心多入口展示权限控制

## 背景

本稿处理来源会话 `019ee819-84a2-7012-a12d-87bedb83fe00` 下的需求主题：`关于需求分析：个人中心入口权限控制`。前序版本已将优坐标个人中心入口控制识别为后台全局配置需求；本次根据用户补充和截图，将配置对象从“招募老师单入口”扩展为优坐标家长端、优坐标教师端个人中心中的 6 组入口展示控制。

本次范围只处理优坐标个人中心入口是否展示、跳转承接、图片配置、全局与单用户控制、权限和生效规则；不处理各入口进入后的完整业务流程、支付流程、分销结算规则或创客中心内部页面细节。

## 目标

- 明确优坐标家长端、教师端个人中心 6 组入口的展示配置范围。
- 区分独立运营页全局配置与家长管理、老师管理中的单用户独立控制。
- 明确单用户独立控制优先于全局配置，避免下游流程、交互和数据交互阶段出现规则冲突。
- 为后续业务流程、信息架构、交互设计、数据交互和高保真原型修订提供统一需求边界。

## 关键结论

- 配置对象是优坐标家长端、优坐标教师端个人中心中的 6 组入口是否展示：`招募老师`、`申请加盟`、`邀请家长报名`、`招募合伙人`、`创客中心`、`会员开通`。
- `邀请老师入驻` 与 `招募老师` 是同一入口的前端文案差异，不作为两个独立配置对象。
- `会员开通` 包含普通会员和卓越会员两张会员卡，两张卡需要分别支持独立展示控制。
- 独立运营页用于统一配置家长端、教师端个人中心 6 组入口是否展示。
- 家长管理、老师管理支持对单个用户做入口展示独立控制。
- 单用户独立控制优先于全局配置：全局关闭但单用户开启时，该用户可见；全局开启但单用户关闭时，该用户不可见。
- 家长端和教师端共用同一套文案、图片和跳转页面，不做两端独立素材。
- 跳转范围支持固定页面、表单、外链；海报按固定页面或运营页面承接。
- 图片不是必填项；图片规格尺寸、格式和大小待定。
- 权限边界按系统权限配置决定；后台给哪个角色配置了权限，哪个角色就能编辑全局配置。
- 配置保存后前后端立刻生效。
- 入口关闭后，历史链接或详情页直接访问禁止打开，并展示不可访问或已关闭状态。

## 验收标准

| 需求 | 验收标准 | 不包含内容 |
| --- | --- | --- |
| 多入口配置定位 | 需求文档中配置对象明确为 6 组入口，不再限定为招募老师单入口 | 不包含领榜端入口配置 |
| 全局配置 | 独立运营页可配置家长端、教师端 6 组入口是否展示 | 不定义具体页面布局 |
| 单用户独立控制 | 家长管理、老师管理可对单个用户配置入口展示；单用户配置优先于全局配置 | 不定义具体字段和接口 |
| 招募老师入口 | 可控制“招募老师/邀请老师入驻”入口展示 | 不拆成两个独立配置对象 |
| 申请加盟入口 | 可控制申请加盟入口展示 | 不定义加盟申请表单字段 |
| 邀请家长报名入口 | 可控制邀请家长报名入口展示 | 不定义邀请关系和返佣规则 |
| 招募合伙人入口 | 可控制招募合伙人入口展示 | 不定义合伙人审核和结算流程 |
| 创客中心入口 | 可控制创客中心模块展示；关闭时隐藏团队卡、提现条和相关二级入口 | 不定义创客中心内部收益计算 |
| 会员开通入口 | 可控制会员开通入口展示，普通会员卡、卓越会员卡分别支持独立展示控制 | 不定义会员支付和权益开通流程 |
| 共用内容配置 | 家长端、教师端使用同一套文案、图片和跳转页面 | 不做两端独立素材 |
| 跳转配置 | 点击入口后进入后台配置的固定页面、表单或外链；海报按固定页面/运营页面处理 | 不输出接口字段或路由实现 |
| 图片配置 | 图片不是必填；有图片则按后台最新配置展示，无图片不阻断保存 | 不定义图片上传技术方案和最终规格 |
| 关闭后访问控制 | 入口关闭后，个人中心不展示入口；历史链接或详情页直接访问被禁止，并展示不可访问或已关闭状态 | 不定义具体错误码 |
| 权限控制 | 具备系统配置权限的后台角色可以编辑全局配置；无权限角色不可编辑 | 不固定具体角色名称 |
| 配置生效 | 保存配置后，前端展示状态、文案、跳转、图片和访问控制立刻按最新配置生效 | 不定义缓存刷新机制 |

## 风险与依赖

- 本稿已从“招募老师单入口”升级为“个人中心 6 组入口配置”，下游不得继续按单入口理解。
- `邀请老师入驻` 与 `招募老师` 已合并为同一入口，避免重复配置。
- `会员开通` 下普通会员、卓越会员两张卡已确认需要单独控制。
- 创客中心内部收益、团队、提现规则不在本稿展开；本稿只控制入口和模块是否可见。
- 图片最终规格未确认，会影响视觉设计和素材验收，但不阻塞需求分析。
- 若后续业务希望做城市、渠道、人群、灰度或定时控制，需求范围会扩大，应单独确认版本边界。
